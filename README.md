# EVAL_SPACE — a clean trainset/testset for an exact comparison

Built 2026-08-21 so that **mids9c, GSD, SeLop, FFAA (Qwen3.5-4B) and PE-SPC can be compared on data
none of them selected on**. It exists because the previous comparison was invalid:
`mids_testset.json` is the **validation set** those models chose checkpoints on — SeLop's `--val_data`,
the 9-class `M9_VAL`, GSD's `val_data` **and** `anchor_data` (its dual-stream anchor is built from that
set and embedded in the checkpoint), and FFAA's MIDS-4c head validates on a manifest that is 100.0%
the same 30,197 records. Re-scored under one harness they read 0.999916–1.000000 AUC, which is
selection fit, not detection.

## What is here

| file | n | real | pad | deepfake |
|---|---|---|---|---|
| `dataset/trainset.json` | 940,014 images | 322,081 | 345,067 | 272,866 |
| `dataset/testset.json` | 241,667 images | 87,271 | 109,922 | 44,474 |

Both are **mids format**, generated by the merged **ffaa-qwen3.5-4b**
(`PAAS_ensemble_v4_inf/weights/qwen35_4b_merged`) via `PAAS_ensemble_v4/qwen/gen_mids_vllm.py`:

```json
{"id": "...", "image": "/abs/path", "cls_label": 0|1,
 "answers": [{"content": "Image description: ...\nForgery reasoning: ...",
              "result": "real|fake", "label": 2*cls_label + claim}, ... x3]}
```

`cls_label` is **binary** and derived from the PATH (`get_label_all`), not from any stored field. The
3-class label (real/pad/deepfake) also comes from the path; 9-class members use `3*true + claim`.

## How the trainset was cleaned

Source: `/datasets/newout/vqa_info_2+13+4+3_fmt/mids_first_half.json`.

1. Records whose file does not exist were dropped (the manifest is stale: 350,034 records point into an
   emptied directory) → 1,360,956 usable rows.
2. **De-duplicated by CONTENT, not by path.** 1,360,956 rows cover only 986,703 distinct paths and just
   **940,299 distinct feature vectors** — the same image is stored under different paths (one cluster is
   231 byte-identical copies of one real image across separate user directories). Path-dedup alone
   would have left ~46k duplicate images.
3. The **285 content clusters with contradictory labels** (1,815 rows; 276 pad+deepfake, 9
   real+deepfake — the same UUID filed under both `fake/pad/` and `fake/deepfake/`) were removed
   entirely: de-duplication collapses a cluster to one row, and where members disagree there is no
   defensible choice of label.

Result 940,014 (30.9% smaller than the source). **Expect lower absolute accuracy than the old runs:**
de-duplication measurably costs 0.105 fake-recall and 0.178 PAD recall, because the repetition was
acting as source-frequency weighting aligned with the old evaluation distribution. That cost applies
to every model equally, so the ranking stays fair — which is the point of this directory.

## How the testset was cleaned

Source: images under `/datasets/work/vLLM/data/no_delete_mids_train` (1,366,146 files). The trainset was
originally cut from this folder and images were added afterwards, so the additions are held out by
construction.

1. **Path-disjoint**: 1,366,146 folder images − 945,146 used by the trainset = **421,000 candidates**
   (0 trainset paths have gone missing from the folder).
2. **14,400 exact content duplicates of trainset images removed (3.42%)** — new paths, old content.
   Path-difference alone would have leaked every one of them. Found by HASHING feature rows, never by a
   cosine cut: the fp16 cache stores vectors with norms 0.9956–1.0049, so a raw dot of two identical
   rows is ‖v‖² ∈ [0.9913, 1.0098] and a ≥0.9999 cut misses ~40% of them.
3. **7,203 duplicates within the candidate pool** removed.
4. **Near-duplicates at cosine ≥ 0.98 removed** (160,756). 0.98 rather than 0.99 because a JPEG
   re-encode of the *same* image measures cosine mean 0.9878 / min 0.9388 on this encoder, so a 0.99
   cut lets re-encodes through. Full sensitivity table over nine thresholds: `runs/testset_dedup.json`.

Features for all comparisons come from the frozen PE-Core-G14-448 encoder, fp32-renormalised before any
cosine.

## Reproduce

```bash
python build_clean_testset.py --thresh 0.98      # needs cache/cand_*.npz (PE features)
bash run_gen.sh measure                          # throughput probe
bash run_gen.sh all                              # testset then trainset, 4 shards on 4 GPUs
python check_gen_coverage.py --images work/testset_clean_images.json \
    --merged dataset/testset.json --errors 'work/mids_test_*.json.errors.json'
```

## Caveats to carry into any result computed here

- `gen_mids_vllm.py` **deliberately drops low-quality real images** (`lowq_real`) during generation, so
  the mids output is smaller than the image manifest and the real fraction shifts. Applied identically
  to both sets; reconciled by `check_gen_coverage.py`, which fails on any loss it cannot attribute to a
  recorded reason.
- The testset is the *new* part of one folder, so it is not an independent capture campaign — it shares
  rigs and identities with the trainset. It is disjoint in content, not in domain.
- Removing near-duplicates biases the testset toward images unlike the trainset. That penalty falls on
  every model equally, so it does not distort the ranking, but it does make absolute numbers harder
  than the old testset's.
